# FunnelStream data model review (read-only, 10 October 2026)

Reviewer scope: contracts, Bronze/Silver, Gold SQL and build, live Postgres, the inventory spec and plan, docs/metrics.md, and the Power BI model design. Nothing was run. Line numbers are file lines unless marked "plan N" (line N of docs/superpowers/plans/2026-10-10-inventory-two-users.md). Anything I could not confirm by reading is marked UNVERIFIED. Important: the inventory work is only partly built. The Silver stock tables, the validator, the store map and the simulator ledger exist; the live Postgres tables, express tables, inventory_daily, oos_demand_daily, express_daily, the D-1 marts and the Power BI inventory tables exist only in the plan and design documents (warehouse/live_ddl.sql today holds only the four health tables). So findings about the planned marts are findings about the design, which is the cheapest moment to fix them.

## 1. Verdict

1. The existing Gold model (dimensions, order facts, attribution, four aggregates) is unusually rigorous: stated grain, idempotent MERGEs with tombstones, SCD2 with overlap checks, ratio-of-sums in Power BI. It will survive an examiner.
2. The weak point is the new bridge metric, "estimated spend exposed to out-of-stock". Its out-of-stock flag is decided at the moment the live sink writes, not at event time, so it is not replay-safe, and its numerator and denominator come from different sources with different click definitions.
3. One time-handling contradiction touches the headline Campaign page too: ad spend is a UTC day, orders are a Cairo day, and the SQL, the docs and the two inventory documents each say something different.
4. Express orders (the 20-minute promise) live only in a side table; Gold, Power BI sales and the Store dimension cannot see them, and the SLA logic has unhandled edge cases (cancelled orders, late delivered events, frozen daily rows).
5. Counts: 3 Critical, 12 Important, 10 Minor. Everything Critical and most Important can be fixed or at least stated honestly in the 2 days left; section 4 gives the order.

## 3. Done well

- Every Gold table has a stated grain, a key list in one specification module (warehouse/tables.py) from which both the Delta and the Postgres DDL are generated, so the dialects cannot drift. Float is forbidden; money is decimal.
- All aggregates are "recomputed, never incremented" in a single atomic MERGE with tombstone deletes (fact_attribution) or NOT MATCHED BY SOURCE (aggregates), so a failure leaves the window intact and a rerun is a no-op.
- SCD2 is handled carefully: one version per day, valid_from inclusive and valid_to exclusive, valid_to only ever shrinks, a second MERGE closes versions left over by collapse, and the fact joins use ROW_NUMBER so a dimension fan-out cannot multiply facts. The SCD2 invariants (one current, no overlap) are data quality checks.
- Attribution is fully specified (click definition, three-step resolution, tie breaks, two rows per order, a parity test against a Python reference) and the metric dictionary matches the SQL; I found no case where docs/metrics.md contradicts a Gold SQL file except C1.
- Time handling is deliberate where it was thought through: Cairo date through `from_utc_timestamp`, a forced UTC session, late events recomputed by kafka_timestamp, and the funnel's non-additive sessions are stated in three places.
- Power BI design: star schema with four dimensions, single-direction many-to-one relationships, rate columns hidden, every ratio a ratio of sums with DIVIDE, "spend days" logic, semi-additive Closing Stock, a weighted average for express minutes, and a rule that zero breaches shows 0.
- The stock contract is strict (integers only, sign per reason, required order_id on sold), uses the standard envelope, and an explicit transform branch makes it impossible to parse a stock event as an order.
- The inventory design recomputes stock from snapshot plus later movements (order independent, tolerant to duplicates), the daily mart is dense per store and product, and `oversold_units` is honest about being a lower bound.
