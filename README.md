## Gold tables

Written only by the Databricks Gold build (spec section 17, rule 13). Full definitions in [docs/metrics.md](docs/metrics.md).

| Table | Role |
|---|---|
| `dim_customer`, `dim_product`, `dim_campaign`, `dim_date` | Dimensions. Surrogate keys are `GENERATED BY DEFAULT AS IDENTITY`; key -1 is the unknown member (not `dim_date`) |
| `fact_orders`, `fact_order_lines`, `fact_attribution` | Base facts, one row per order, order line, and order and attribution model |
| `agg_orders_daily` | Orders and revenue by day, channel, payment method, platform |
| `agg_funnel_daily` | Sessions and abandon rates by day, country, channel, platform |
| `agg_campaign_daily` | Campaign spend, orders and ratios per report date (last touch) |
| `agg_city_product_daily` | City, product, day views, carts and sales |
| `rec_product` | Co-view product recommendations |
| `customer_360` (stretch) | Customer current state |

## Address and tracking

An address is country, city, then district (spec section 18). Districts are the official Egyptian subdivisions of each city (for example Nasr City, Maadi and Heliopolis under Cairo; Dokki, Agouza and Imbaba under Giza); a missing or mismatched district is stored as `unknown`. Campaign traffic is tracked by UTM parameters inside the page URL (`page_url`); Silver parses `utm_source`, `utm_medium` and `utm_campaign` from it.

## Yesterday's ad report

Airflow DAG `ads_yesterday_report` (03:00 UTC daily, `airflow/dags/`, logic in `batch/ads_report.py`) pulls the ad API for yesterday once, stores it in `silver_campaign_snapshots` and writes `data/reports/ads_report_<date>.json`. A rerun on the same day returns the stored report without calling the API. Start Airflow with `docker compose --profile airflow up -d airflow`. Details in [docs/RUNNING.md](docs/RUNNING.md).

## Getting started

```bash
cp .env.example .env            # set your own passwords
python -m venv .venv
.venv/Scripts/activate          # Windows
pip install -r requirements.txt
pytest
```

Spark tasks (7 onward) run in Docker. The host needs Python 3.11 only for the simulator and the host tests. Java is NOT needed on the host: Java is inside the Spark Docker image. See [docs/RUNNING.md](docs/RUNNING.md).

## Spark in Docker

Spark needs Hadoop's winutils on Windows, so Spark runs in a container. Spark tests are skipped on the Windows host unless `RUN_SPARK_TESTS=1`.

```bash
docker compose build spark
docker compose run --rm -e RUN_SPARK_TESTS=1 spark python -m pytest tests/test_bronze.py -q
docker compose run --rm spark python -m streaming.jobs.bronze_ingest   # needs Kafka up
```

## Working together

- Branch from `main`, one branch per task (`task-N-short-name`), open a pull request, get one review.
- Do not commit `.env`, `.venv/`, or data under `data/`.
- Every Gold table is written only by the Databricks Gold build. The local Spark stream writes only Bronze, Silver and live metrics. See the spec, sections 3 and 16.
